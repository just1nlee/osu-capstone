# MediaPipe tmux Companion Implementation Plan

> Historical implementation milestones. The [README architecture and development guide](README.md#architecture-and-development) describes the current runtime and IPC contract.

**Goal.** Build a standalone macOS Electron companion that recognizes hand gestures in the background and runs commands against an existing local tmux session.

**Architecture.** One Electron renderer owns the camera, MediaPipe, the gesture state machine, and the two-panel UI. Electron's main process owns session discovery, saved mappings, dispatch validation, and short-lived `execFile` calls to tmux. The user's usual terminal runs its own tmux client.

**Stack.** Reuse the prototype's JavaScript, npm, Electron 45.1.0, and `@mediapipe/tasks-vision` 0.10.35 with the same float16 model. Use Node.js 22.12 or later for tooling and tmux 3.5a as the first verified baseline. Run from source with `npm ci` and `npm start`.

## Scope and sources

- The companion lives in `playground/mediapipe_tmux_companion` in this repository. It reuses recognition techniques from the [original MediaPipe example](../mediapipe-example/MEDIAPIPE_INTEGRATION.md).
- This prototype follows the capstone's goals of keeping the existing terminal and making the camera optional (FR-10/11), providing gesture diagnostics (FR-14), and persisting remaps (FR-15). It uses tmux, Electron-owned recognition, and CLI dispatch. The accepted capstone ADR describes a C multiplexer with a separate headless recognizer and local socket intents. The product toggle owner remains proposed. The full command catalog and frame-count stabilization are prototype behavior. [ADR-0001](https://github.com/just1nlee/osu-capstone/blob/5b6f3e8/docs/adr/0001-hybrid-multiplexer-architecture.md), [ADR-0002](https://github.com/just1nlee/osu-capstone/blob/5b6f3e8/docs/adr/0002-recognition-toggle-owner.md), [requirements](https://github.com/just1nlee/osu-capstone/blob/5b6f3e8/docs/requirements.md), [design](https://github.com/just1nlee/osu-capstone/blob/5b6f3e8/docs/design.md)
- The app uses a local tmux CLI and user-owned server. The scope excludes an embedded terminal, PTY, xterm.js, control mode, shell I/O, command stdout display, HTTP, gesture-related keyboard bindings, key recording, and automatic tmux configuration. A manually configured gesture may still invoke a tmux command whose own effect is to alter sessions or keys. Closing the companion never issues a tmux cleanup command.
- Camera frames and diagnostics stay in memory on the device. Ship the matching WASM with the local model setup, allow only video from the trusted renderer, and keep tests free of saved camera frames. Release packaging and installation at login are outside this plan.

For the implemented flows, see [session discovery and command dispatch](docs/TMUX_INTEGRATION.md), [model settings and recognition](docs/MEDIAPIPE_RECOGNITION.md), and [gesture mappings and validation](docs/GESTURE_MAPPINGS.md).

## Implementation milestones

### 1. Start Electron and discover existing sessions

**Files.** Package and assets docs, `electron/{main,preload,protocol,tmux,session-selection}.cjs`, `renderer/{index.html,style.css,main.js}`, `tests/{session.test.cjs,tmux.integration.test.cjs}`.

- [x] Add tests for zero, one, and many sessions, renames, selected-session disappearance, and replacement of a server with the same session name and ID. Verify manual refresh after starting tmux, preservation of a valid selection, and no fallback on loss. Add a real tmux test that starts with a nonexistent private socket and proves both discovery and catalog calls leave it nonexistent.
- [x] Implement `resolveTmuxPath(signal)` using PATH and the usual Homebrew locations. Implement `createTmuxClient({ binary, socketArgs })` with `discover(signal)`, `listCommands(signal)`, `readContext(session, signal)`, and `runAction(argv, signal)`. Use `execFile` with argv, no shell, `-N` before the socket option, a 750 ms timeout, and a 64 KiB buffer. Strip inherited `TMUX` and `TMUX_PANE`. Preserve `TMUX_TMPDIR` for default/named sockets. Keep CLI errors distinct from an empty server.
- [x] Have `discover` parse fixed, tab-separated fields `session_id`, `pid`, `start_time`, `session_created`, `session_attached` followed by the label. Use the first five columns as metadata and the remaining text as display name. Use the configured socket, server PID and start time, session ID and creation time as identity. Coalesce overlapping refresh requests. Abort or discard results from obsolete selection work. For `readContext`, verify the session identity and query `list-windows`, `list-panes`, and, when needed, `list-clients` scoped to the session. Give command preparation `{ sessionId, activeWindowId, activePaneId, windows, clients }` with indexed windows/panes and active markers. Never resolve targets by a name displayed in the dropdown.
- [x] Implement `createSessionSelection()` with `applyDiscovery(result)`, `select(key)`, and `snapshot()`. Connect the header, initial discovery, manual refresh, and selected-session polling to main state. Ensure repeated polls do not rearm or fall back to a different target.
- [x] Run `node --test tests/session.test.cjs` and `npm run test:tmux`. Start Electron without a tmux server. Check the empty state and refresh after starting a session in a separate terminal.

- [x] Keep the BrowserWindow alive on close and explicitly set `backgroundThrottling: false`. Reuse the FPS-limited inference loop and check for new video frames. - [x] Run `node --test tests/gesture-gate.test.mjs` and `npm run test:app` with generated video. Verify the hidden window still processes frames, capture can be turned off while hidden, the video tracks stop on Off, and reopening shows the latest result.

### 3. Save and validate one mapping per gesture

- [x] Implement the command forms and `prepareCommand(metadata, binding, context)`. Cover `select-pane`, `split-window`, `new-window`, `rename-window`, layout commands, `move-pane`, `join-pane`, and direct close commands. Assert exact argv for the default pane cycle, a spaced window name, explicit source and destination for a pane move, and a command with a required value. Add failure cases for one pane, one window, and zero or multiple eligible clients. For ordinary argv values ending in `;`, encode a backslash before the final semicolon at the tmux argument boundary because tmux treats it as a command separator even with execFile. Test round-tripping literal spaces and semicolons with a real server. Keep user strings out of any internally built tmux conditional command text.
- [x] Render the live catalog in each row, required values as labeled fields, and optional advanced arguments behind disclosure. Save only valid configuration, with per-row messages. - [x] Run `node --test tests/config.test.mjs tests/commands.test.mjs` and `npm run test:app`. Verify assignment and disabling in Electron and reloading stored bindings in the settings tests.

### 4. Dispatch gestures and verify from an ordinary terminal

**Files.** `electron/{dispatch,tmux,main,preload}.cjs`, `renderer/{main,gesture-gate,debug}.js`, `tests/{dispatch.test.cjs,tmux.integration.test.cjs,app.test.cjs}`, `README.md`.

- [x] Implement `createDispatcher({ getState, getSession, getMappings, getCommands, tmux, now })` with `dispatch(request)` and `cancelPending()`. Validate gesture, saved mapping revision, target token, camera generation and guard in main. Recheck them after async target resolution, allow one action in flight, and drop stale or busy requests. Re-resolve against the selected server/session at every action. A return or error from a stale action cannot change the new selection. Treat timeout as an uncertain outcome and do not automatically retry an action.
- [x] Carry over the original conservative guard. Default focus and layout commands with reviewed arguments can fire on stabilization. Close, shell execution, server-wide changes, and unfamiliar command/argument combinations require the checkbox and a one-second gesture hold. Main measures the elapsed hold and validates the same saved binding and resolved targets at commit. For `move-pane`, a guarded attempt pins both source and destination. Direct `kill-pane`, `kill-window`, and `kill-session` target only the selected live pane/window/session; reject bulk close flags and alternate targets on those direct commands. For direct closes use a trusted tmux `if-shell -F` with explicit scoped IDs and an in-server context check, including a last-pane condition for `kill-pane`. Only validated identifiers enter the internal conditional command. Surface an explicit cancellation if its condition fails. Explain in the README that a user-configured generic command can have server-wide or nested effects.
- [x] Add tests for closed guard, short hold, held pose firing once, disabled and unassigned rows, stale mapping/session/camera tokens, target changes during preparation or a guarded hold, last-pane protection, one-window move failure, and background dispatch. Verify a default focus gesture affects only the selected session, and verify successful same-window and cross-window moves by comparing pane IDs before and after.
- [x] Run `npm ci`, `npm test`, `npm run test:tmux`, and `npm run test:app`. Require the tmux acceptance run to execute against a real binary, with `TMUX_TEST_BINARY` available for a non-PATH installation. Test fixtures create only temporary sockets and clean up only servers they started. Confirm startup has no IPC or asset errors and dependencies contain no terminal renderer or native module rebuild.
- [ ] Conduct a macOS live run using the user's ordinary terminal and a disposable two-pane tmux session. Start the companion first and verify refresh detects a session started later. Map and perform a pose with the companion hidden and the terminal focused, then disable that gesture and check that it stops firing. Check `move-pane` and the guard using disposable panes. Quit and confirm the session, pane processes, and tmux's keyboard bindings still work. Record pass/fail and optional derived timings. Save no footage or screenshots showing a recognizable person.

## Handoff criteria

Acceptance criteria include the late-start/no-session flow, one-session auto-selection, a dropdown for multiple sessions, and a session ending while a pose is held. A configured gesture runs in the selected tmux session while the companion window is hidden. The same window shows MediaPipe diagnostics next to all seven mapping rows. A row retains its command while disabled. A known missing prerequisite appears as a specific message before execution, and unknown tmux errors include a readable cause. The usage guide explains launch, the named-socket override, camera control, how to map and check a command, which commands require a hold, and how to verify a command in a disposable session.

## Verification record

Verified normal startup with a disposable session on macOS, the seven-row layout, and camera off at launch. The integration suites exercise tmux 3.5a and 3.8. The Electron smoke test exercises generated video, the Chromium fake camera through Electron's media permission handlers, and a synthetic label flowing through the real gesture state machine to a real tmux client attached to a test PTY. The physical webcam and recognition of a real hand remain to be verified manually.

The model is now read from the repository’s ignored `test-model/models/gesture_recognizer.task` file. Unit tests verify the shared model route, and the Electron smoke test compares the served bytes with the file on disk. See [shared model setup](docs/MEDIAPIPE_RECOGNITION.md).
